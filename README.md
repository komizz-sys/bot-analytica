# 📊 Analytics Bot — бот-аналитик (доход / расход / прибыль)

Отдельный Telegram-бот, который показывает доход/расход/прибыль твоего
магазина. Ничего не трогает и не ломает в основном боте — просто читает
данные через маленький защищённый API.

## Как это устроено (коротко)

- **Доход** бот-аналитик узнаёт у ГЛАВНОГО бота-магазина (`tg_shop_bot`) —
  тот теперь отдаёт статистику по секретному API-запросу.
- **Аренда NFT** — расход считается **автоматически и точно** (цена аренды
  на MarketApp известна и хранится в заказе).
- **Звёзды / Premium / подарки** — расход НЕ автоматический (ты покупаешь их
  вручную через Fragment), поэтому эти траты нужно **вносить руками** через
  кнопку "💸 Добавить расход" в самом боте-аналитике.
- **Прибыль** = доход − (авто-расход по аренде + все внесённые вручную расходы).

⚠️ Почему нельзя было проще (одна общая база на двоих ботов): Railway **не
поддерживает** общий volume между двумя разными сервисами — я проверил
официально. Поэтому пришлось сделать через API, а не через "прямой" доступ
к одной и той же базе.

## Шаг 1. Создай нового бота у @BotFather

Как обычно — `/newbot`, получишь новый `BOT_TOKEN`. **Это будет отдельный
токен**, не такой как у магазина.

## Шаг 2. Обнови и задеплой tg_shop_bot (bot-worker.zip)

В архиве `bot-worker.zip`, который я прислал вместе с этим — уже добавлен
внутренний API. Просто залей поверх старого репозитория `tg_shop_bot`.

В Railway у сервиса **tg_shop_bot (worker)** добавь переменные:
```
ANALYTICS_API_SECRET=придумай-любую-случайную-строку
STATS_API_PORT=8081
```

### Включи публичный домен для сервиса tg_shop_bot (worker)

Раз это "worker"-сервис, у него по умолчанию нет публичного адреса.
Нужно один раз включить:
1. Открой сервис **tg_shop_bot** в Railway
2. Вкладка **Settings → Networking**
3. Нажми **Generate Domain**
4. **Важно:** укажи порт **8081** (тот же, что в `STATS_API_PORT`)
5. Скопируй получившийся адрес — типа `https://tg-shop-bot-production.up.railway.app`

## Шаг 3. Задеплой этот новый репозиторий (analytics_bot)

1. Создай новый репозиторий на GitHub, залей туда все файлы из этого архива
2. Создай новый сервис на Railway → Deploy from GitHub repo → выбери этот репозиторий
3. Добавь переменные в Railway:
```
BOT_TOKEN=токен_нового_бота_из_шага_1
ADMIN_IDS=твой_telegram_id
SHOP_API_URL=https://tg-shop-bot-production.up.railway.app   (из шага 2, БЕЗ слэша в конце)
SHOP_API_SECRET=та_же_строка_что_в_ANALYTICS_API_SECRET_у_магазина
```

## Шаг 4. Проверка

1. Напиши `/start` новому боту-аналитику
2. Нажми "📊 Сегодня" — должен показать доход за сегодня (если заказов
   сегодня не было — просто нули, это нормально)
3. Нажми "💸 Добавить расход" — впиши сумму и что купил (например
   "Купил 5000 звёзд на Fragment") — расход появится в отчёте

Если бот пишет "⚠️ Не удалось получить данные от магазина" — значит либо:
- Домен для tg_shop_bot ещё не сгенерирован (Шаг 2)
- `SHOP_API_SECRET` не совпадает с `ANALYTICS_API_SECRET`
- Порт в Generate Domain указан не тот, что в `STATS_API_PORT`

## Как считается доход/расход (если интересно)

- **Доход** — сумма `price_uzs` всех заказов со статусом `paid`,
  `fulfilling` или `completed` (то есть оплата подтверждена админом).
  Заказы, где оплата ещё не подтверждена или отклонена, не считаются.
- **Расход по аренде** — приблизительный: `цена_за_день_в_GRAM × дни ×
  текущий_курс_TON`. Курс на момент самой аренды не хранится, так что при
  сильных скачках курса цифра будет немного отличаться от факта.
- **Остальной расход** — только то, что ты сам внёс вручную.
